Rendering 100k sensor readings with LTTB

A thermal sensor sends a reading every 5 seconds. A week of that is 120k points per sensor. Chart.js froze on the full series, so every render downsamples to 2,000 points with LTTB, on the visible window only.

The problem: 120k points into Chart.js

ThermalTrack collects a reading from every sensor every 5 seconds. One sensor produces 17,280 readings a day and 120k+ in a week. The chart endpoint returns the full series for the date range, so the browser had to draw all of it.

Chart.js with 120k points froze the dashboard. Panning dropped frames. Tooltips took a second. Zoom made it worse: the whole array went through the renderer again on every frame.

Why every Nth point fails

Dropping every Nth point kills the peaks. Temperature alarms live in the peaks. A one-minute spike over the critical threshold can be the only point in an hour that matters, and N-th sampling can skip it.

LTTB (Largest Triangle Three Buckets) picks the points the shape needs. It splits the series into buckets. For each bucket it keeps the point whose triangle with the previous anchor and the next bucket's average has the biggest area. O(n), one pass:

function downsampleLTTB(data: NumPoint[], threshold: number): NumPoint[] {
  if (data.length <= threshold || data.length <= 3) return data;

  const out: NumPoint[] = [data[0]];
  const bucketSize = (data.length - 2) / (threshold - 2);
  let a = 0;

  for (let i = 1; i < threshold - 1; i++) {
    const rangeStart = Math.floor((i - 1) * bucketSize) + 1;
    const rangeEnd = Math.min(Math.floor(i * bucketSize) + 1, data.length);
    const nextStart = Math.floor(i * bucketSize) + 1;
    const nextEnd = Math.min(Math.floor((i + 1) * bucketSize) + 1, data.length);

    if (nextStart >= nextEnd || rangeStart >= rangeEnd) continue;

    let avgX = 0, avgY = 0, count = 0;
    for (let j = nextStart; j < nextEnd; j++) {
      if (data[j].y === null) continue;
      avgX += data[j].x;
      avgY += data[j].y;
      count++;
    }
    if (count === 0) continue;
    avgX /= count;
    avgY /= count;

    let maxArea = -1, maxIdx = rangeStart;
    for (let j = rangeStart; j < rangeEnd; j++) {
      if (data[a].y === null || data[j].y === null) continue;
      const area = Math.abs(
        (data[a].x - avgX) * (data[j].y - data[a].y) -
        (data[a].x - data[j].x) * (avgY - data[a].y)
      );
      if (area > maxArea) { maxArea = area; maxIdx = j; }
    }
    out.push(data[maxIdx]);
    a = maxIdx;
  }

  out.push(data[data.length - 1]);
  return out;
}

The result: 120k points become 2,000, and the spikes survive.

Slice the window first

Downsampling the full series on every zoom wastes time. The visible range is a small fraction of the data.

Two binary searches (bisectLeft, bisectRight) find the visible window. The slice gets 2% padding plus 3 extra points on each side, so lines enter and leave the viewport correctly at deep zoom. Then LTTB runs on the slice:

const SMALL_SERIES_POINTS = 1000;
const MIN_EXTRA_POINTS = 3;

// simplified: empty-range fallback omitted
function sliceAndDownsample(full: NumPoint[], xMin: number, xMax: number, maxPts: number) {
  if (full.length <= SMALL_SERIES_POINTS) return full;   // small series render as-is
  if (xMin > xMax) [xMin, xMax] = [xMax, xMin];

  const padding = (xMax - xMin) * 0.02;
  let i0 = Math.max(0, bisectLeft(full, xMin - padding));
  let i1 = Math.min(full.length, bisectRight(full, xMax + padding));
  i0 = Math.max(0, i0 - MIN_EXTRA_POINTS);
  i1 = Math.min(full.length, i1 + MIN_EXTRA_POINTS);

  const slice = full.slice(i0, i1);
  if (slice.length <= maxPts) return slice;
  return downsampleLTTB(slice, maxPts);
}

Deep zoom: the slice is small, so LTTB returns almost everything in range. Overview: the full series compresses to 2,000 shape-preserving points. One function covers both.

Zoom without re-initializing

Zoom and pan run through chartjs-plugin-zoom on the x axis (wheel, drag, pinch). On zoom end the chart reslices the visible window and calls chart.update("none"). No animation pass, no re-init, same canvas.

Details that matter:

  • parsing: false. Timestamps are normalized to ms once, before Chart.js sees them. The library never parses a date.
  • The y axis is fixed from the full dataset. It does not jump while you zoom.
  • minRange is the smallest gap between samples. You can't zoom past the data's resolution.
  • The x axis targets ~50 ticks and switches units by visible range: minute, hour, day.

Live data while zoomed

New readings arrive while the dashboard is open. If the user is zoomed within 5% of the last point, the window auto-follows and keeps its width. If the zoom is elsewhere, it stays and only the visible window redraws. Either way, the canvas never receives more than 2,000 points.

The same algorithm, server side

The browser fix was not enough. Old data keeps growing, and nobody needs 17,280 points per day for a sensor from three months ago.

A nightly job runs the same LTTB on readings older than 30 days and keeps 3,000 points per sensor, 20 sensors in parallel. The database stores the compressed history; the client re-compresses every render.

Lessons

  • Downsample at the last moment, on the visible window. Anything earlier wastes work.
  • Keep the shape, not the cadence. LTTB keeps spikes; every-Nth keeps rhythm and loses events.
  • Range slicing is binary search, not a filter. Two bisects turn 120k points into a visible slice without a scan.
  • The same algorithm runs twice: in the browser for rendering, in the nightly job for retention.

The whole fix is about 40 lines of LTTB and two binary searches. The dashboard stays interactive at any zoom level, and the chart endpoint still returns the full series, untouched.
